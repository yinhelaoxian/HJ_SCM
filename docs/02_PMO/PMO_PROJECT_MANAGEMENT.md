## 一、总则

### 1.1 目的

规范马六甲（新加坡）与华生（大陆）双团队协作项目管理流程，确保高效交付，沉淀可复用的协作范式。

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **双核驱动** | 马六甲（规划验收）与华生（分析开发）并行协作 |
| **职责清晰** | 各团队边界明确，避免冲突 |
| **闭环交付** | 任务端到端负责，最终由马六甲验收 |
| **文档驱动** | 所有变更和决策均通过文档沉淀 |

### 1.3 适用场景

本制度适用于 HJ_SCM 数字化转型项目及其衍生项目。

## 三、项目生命周期与协作流

### 3.1 阶段划分

```
业务规划 (马六甲) → 需求分析 (华生) → 方案设计 (马六甲) → 代码开发 (华生)
      → 代码提交 (华生) → 部署启动 (马六甲) → 文档审核 (马六甲) → 项目验收 (马六甲)
```

## 四、沟通与协作

### 4.1 协作渠道

| 场景 | 渠道 | 责任团队 | 说明 |
|------|------|----------|------|
| **业务规划** | 飞书/Telegram | 马六甲 | 向华生团队同步业务目标和蓝图 |
| **需求细化** | 飞书/Telegram | 华生 | 向马六甲团队同步 PRD 和设计细节 |
| **代码变更** | GitHub PR | 华生 (提交), 马六甲 (审核) | 代码评审和合并 |
| **部署状态** | 飞书/Telegram | 马六甲 | 发布通知和状态更新 |
| **紧急问题** | 飞书/Telegram | 双团队 | 跨团队协同解决 |

### 4.2 记忆同步规范

1.  **马六甲记忆库**：独立维护 `openclaw_memory_sg` (GitHub) 仓库，记录新加坡节点相关经验与配置。
2.  **华生记忆库**：独立维护其专属记忆库，记录大陆节点相关经验与配置。
3.  **通用信息**：如锋哥的指令和项目总体目标，在各自记忆库中保持一致，但各自的实现细节独立。

## 五、变更管理与代码提交制度

### 5.1 代码提交规范

**责任团队**：华生团队 (代码提交)，马六甲团队 (代码审核)

#### 5.1.1 提交时机
- 华生团队完成任何可运行、可验证的变更后，应**立即提交**。

#### 5.1.2 提交信息规范
- 统一采用 `<类型>: <简短描述>` 格式，并关联 Issue 或任务编号。

### 5.2 Git 分支策略

**责任团队**：华生团队 (分支管理)，马六甲团队 (主分支审核)

- `main` (生产环境) -> `develop` (开发主分支) -> `feature/fix` (功能/修复分支)

### 5.3 代码 Review 制度

**责任团队**：马六甲团队 (Reviewer)，华生团队 (提交者)

- **核心业务逻辑**：马六甲强制 Review。
- **文档更新**：马六甲进行自审或抽查。

### 5.4 版本发布规范

**责任团队**：马六甲团队 (发布管理与验证)

- 采用语义化版本：`主版本.次版本.修订号`。
- 马六甲负责发布前的全面检查清单。
