# HJ_SCM 团队分工与协作规范 (双团队版)

> 本文档定义了 HJ_SCM 项目在新加坡与大陆双节点模式下的团队架构与职责分工。

---

## 👥 双团队架构总览

项目由两个独立的 OpenClaw 团队协作完成，各司其职，共同推进。

### 🇸🇬 团队一：新加坡马六甲 (Team Malacca)
**定位**：业务规划、方案设计与项目验收中心
**主要负责人**：马六甲 (Malacca)

#### 核心职责：
1. **业务规划**：负责项目整体业务蓝图、Sprint 目标与功能架构的规划。
2. **方案设计**：主导技术方案选型、设计系统规范与核心业务逻辑设计。
3. **项目验收**：
    - **代码/文档检查**：审核华生团队提交的代码质量与文档准确性。
    - **部署启动**：负责新加坡生产演示环境的部署、配置与服务器启动。
    - **验收报告**：出具最终的项目验收报告，对项目交付质量负责。
4. **基础设施**：直接连接 GitHub (新加坡节点)，无需隧道。

---

### 🇨🇳 团队二：大陆华生 (Team Watson)
**定位**：需求分析、文档编制与代码开发中心
**主要负责人**：华生 (Watson)

#### 核心职责：
1. **需求分析**：根据马六甲的业务规划，细化业务逻辑，编写详细的需求分析报告。
2. **文档编制**：负责编制相关的技术文档、接口文档及 PRD 细化文档。
3. **代码开发**：
    - **团队模式开发**：指挥子代理 **Claude Code** 启用团队协作模式进行具体代码实现。
4. **提交与测试**：
    - 将代码提交至 GitHub 仓库。
    - 负责大陆节点的本地部署、服务器启动与初步功能测试。
5. **基础设施**：通过 SSH 隧道访问 GitHub。

---

## 🔄 协作闭环流程

1. **规划 (马六甲)**：输出业务规划与方案设计。
2. **分析与开发 (华生)**：编写 PRD -> 指导 Claude Code 开发 -> 提交代码。
3. **部署与验收 (马六甲)**：同步代码 -> 部署服务器 -> 检查代码与文档 -> 输出验收文档。
